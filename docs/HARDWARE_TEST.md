# Проверка на реальном комбике — чек-лист

Редактор проверен только в демо-режиме: у разработчика нет THR10. Этот
чек-лист — что проверить на железе и что прислать при ошибке.
Протокол и статусы команд — [PROTOCOL.md](PROTOCOL.md).

Отмечайте результат: ✅ работает / ❌ не работает / ⚠️ работает не так.

## 0. Подготовка

1. Комбик THR10 (первое поколение) подключён по USB и включён, драйвер
   Yamaha Steinberg USB установлен.
2. **Официальный THR Editor закрыт.** Он держит MIDI-порт, и редактор (и
   скрипт проверки) не смогут его открыть.
3. **Громкость комбика — небольшая** (ручка Volume на комбике). Проверка
   меняет параметры, а ручка Volume программно не управляется.
4. Скрипт проверки: `THR10Probe.exe` из сборки или
   `py -3.12 tools\thr_probe.py` из исходников.

## 1. Скрипт `thr_probe` — первым делом

```bat
THR10Probe.exe
```

или `py -3.12 tools\thr_probe.py`.

Скрипт:
* показывает все MIDI-порты и ищет порт THR;
* ждёт heartbeat (модель комбика);
* запрашивает состояние и выводит **все параметры** (сырое значение →
  отображение);
* делает Master на 5 тише, проверяет, что комбик принял значение, и
  **возвращает исходное** (даже при ошибке или Ctrl+C);
* пишет всё в `thr_probe_<дата>_<время>.log` рядом с собой.

| # | Проверка | Ожидается | Результат |
|---|----------|-----------|-----------|
| 1.1 | Порт найден | строка `Порт: вход «…», выход «…»` | |
| 1.2 | Heartbeat | `модель: THR10` (или ваша модель) | |
| 1.3 | Состояние | список параметров; Gain/Master/Bass/Middle/Treble совпадают с ручками комбика (0–100 ≈ положение ручки) | |
| 1.4 | Изменение Master | `OK: комбик принял amp.master = …`; громкость чуть упала | |
| 1.5 | Возврат | `OK: amp.master снова …`; громкость вернулась | |
| 1.6 | Итог | `Итог: всё в порядке`, код выхода 0 | |

Порт не нашёлся? `THR10Probe.exe --list` покажет имена портов; затем
`THR10Probe.exe --port "точное имя"`.

Синхронизация ручек: `THR10Probe.exe --no-change --listen 30` и крутите
ручки на комбике 30 секунд — в логе должны появиться строки
`← … [изменение параметра amp.gain = …]`.

### 3.9. Единицы времени дилея — важно для тап-темпа

Единица Delay Time (0,1 мс) выведена из источников, не подтверждена.
Проверка:

1. Запустите официальный THR Editor, поставьте **Delay Time = 500 ms**
   (или любое известное значение), закройте его.
2. Запустите `THR10Probe.exe --no-change`.
3. В логе найдите `delay.time  0x31  NNNN → …`.

* если `NNNN` = 5000 → единица 0,1 мс, всё верно ✅;
* если `NNNN` = 500 → единица 1 мс ❌ — пришлите лог, я поправлю константу
  `DELAY_TIME_UNIT_MS`.

Так же можно сверить Reverb Time (ожидается ×0,1 с), Pre (×0,1 мс), High/Low
Ratio (×0,1) и подписи Ratio компрессора Rack.

## 7. Не подтверждено — только перехватом

* **Lamp / Wide** (Настройки → Комбик). Отправка заблокирована. Чтобы
  подтвердить: перехватите трафик, пока переключаете их в официальном
  эдиторе ([CAPTURE.md](CAPTURE.md)), и пришлите отчёт `parse_capture`.
* **Запись в ячейку из программы.** Если в официальном эдиторе есть
  функция сохранения в ячейку комбика — перехватите её тем же способом.

## Что прислать при ошибке

1. Лог `thr_probe_*.log` (запуск из пункта 1).
2. Журнал редактора: `%APPDATA%\THR10Editor\thr10editor.log`
   (путь виден в Настройках) и/или «Журнал MIDI» → «Копировать» (Ctrl+J).
3. Номер пункта чек-листа, что сделали, что ожидали, что получилось.
4. Скриншот, если проблема видна в интерфейсе.
5. Если просил перехват — файл `.pcapng` и вывод
   `parse_capture.py файл.pcapng`.
