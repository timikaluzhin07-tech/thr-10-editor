## Принятые решения

### Этап 1 — протокол

* **Источники.** Основной — SysExTones (адреса и диапазоны всех параметров).
  Раскладку дампа и минимумы независимо подтверждают реальные байты `.YDL`
  из THR_Footswitch и утилита thrpatch. Форумы Yamaha, Википедия и сайт
  Yamaha недоступны из среды разработки — ссылки на них оставлены в
  `docs/PROTOCOL.md` для ручной проверки.
* **Лицензии источников** (AGPL/GPL/BSD): код не копируем, реализуем заново по
  фактам (байты, смещения), источники указываем.
* **Lamp/Wide** (системные команды `30`) — один источник, подозрительный
  формат → `UNCONFIRMED`, не отправляются.
* **Запись в ячейки 1–5**: SysEx-команды нет в источниках → редактор
  отправляет звук в текущее состояние, сохраняет пользователь удержанием
  кнопки на комбике. Чтение ячейки — через дамп, который комбик шлёт при
  нажатии кнопки.
* **Единицы отображения** (0,1 мс, 0,1 с, «Thru») — `DERIVED`, на байты не
  влияют. Единица Delay Time вынесена в константу — от неё зависит тап-темп.

### Этап 2 — протокол и модель

* **Стек и версии** (проверено в среде разработки): Python 3.12/3.13,
  PySide6 6.12.0, mido 1.3.3, python-rtmidi 1.5.8, pytest 9.2.0,
  PyInstaller 6.22.3. **Для Windows — Python 3.12 (64-bit)**: у
  python-rtmidi 1.5.8 нет колёс для Windows под Python 3.13+, а сборка из
  исходников требует MSVC. Выбор PySide6 + QML — по ТЗ; QML даёт плавные
  анимации, масштабирование и HiDPI без ручной отрисовки.
* **Логические значения в модели.** Вкл/выкл хранится как 1/0, а в протоколе
  00 = вкл, 7F = выкл. Перевод делает `ParamDef.to_raw/from_raw`.
* **Параметры разных типов эффекта** (Stomp/Rack, Chorus/Flanger/…,
  Hall-Room-Plate/Spring) делят адреса. В модели они хранятся раздельно
  (`comp.stomp.sustain` и `comp.rack.threshold`), в дамп пишутся только
  активные. При разборе дампа значения неактивных типов берутся из
  текущего состояния — переключение типа не теряет настройки.
* **SafetyGate** — последний фильтр перед комбиком: пропускает только
  изменение известного параметра в допустимом диапазоне, запрос состояния
  и корректный дамп. Неподтверждённые команды открываются только через
  `protocol_overrides.json`.
* **Имена пресетов на комбике**: только ASCII, ≤ 64 символа; кириллица
  транслитерируется (в библиотеке редактора имя хранится как есть).
* **Тестовые данные**: реальные байты двух пресетов из THR_Footswitch
  (`tests/fixtures.py`) — проверяют раскладку дампа и чтение .YDL.

### Этап 3 — транспорт

* **Один интерфейс** `Transport` (`open/close/send/poll`) для MIDI и демо.
  Приём — опросом (`poll`) из такта сессии: без потоков, безопасно для Qt.
* **Демо-комбик** (`DemoAmp`) работает на уровне байтов SysEx через тот же
  слой протокола: отвечает дампом на запрос, шлёт heartbeat 2 раза/с,
  умеет «крутить ручки» и «нажимать кнопки ячеек» — так проверяется
  синхронизация без железа.
* **MidiTransport** ищет порт по подстроке «THR» (предпочитает вход и выход с
  одинаковым именем), каждое сообщение проверяет `SafetyGate`. Если
  python-rtmidi недоступен — понятная ошибка, приложение остаётся в демо.
* **Ограничение частоты**: ≤ 1 сообщения за 20 мс, склейка по параметру,
  барьеры на смене типа, пауза 60 мс после дампа.
* **Сессия** (`app/session.py`, без Qt): статус связи (heartbeat/таймауты),
  подавление эха (если комбик вернёт наше же значение в течение 0,6 с, оно
  игнорируется), повторный запрос состояния после смены типа/модели
  ручкой на комбике, автопереподключение раз в 3 с после ошибки.
* **Загрузка пресета** уходит одним дампом; правки, морфинг и LFO —
  отдельными сообщениями; undo/рандом — отдельными, если изменений ≤ 8,
  иначе дампом.

### Этап 4 — дизайн

* **Направление «Graphite & Glow»**: графитовая тёмная тема + тёплая светлая,
  один янтарный акцент (отсылка к подсветке THR), свой оттенок у каждого блока
  эффектов. Подробно — `docs/DESIGN.md`.
* **Токены** — `thr10editor/ui/theme/tokens.json`; в QML доступны через
  синглтон `Theme` (размеры уже умножены на масштаб). Тест проверяет
  одинаковость ключей тем и контраст WCAG.
* **Шрифт Inter** (OFL) встроен в TTF: npm-пакет `inter-ui` 4.1.1 (woff2)
  сконвертирован fontTools. Причина — одинаковая типографика на любой
  Windows, кириллица и табличные цифры.
* **Светлый акцент** затемнён до `#A35E00`, чтобы белый текст на кнопках
  имел контраст ≥ 4,5:1.

### Этап 5 — базовый интерфейс

* **QML + синглтоны** `Theme` и `Backend` (модуль `THR10`). Каждому параметру
  соответствует `ParamItem` (значение, текст, положение ручки, активность),
  каждому блоку — `GroupItem` (вкл/выкл, тип, список ручек для текущего типа).
* **Стиль Qt Quick Controls — Basic**: нативный стиль Windows не даёт полностью
  перекрасить контролы под токены.
* **Логарифмическая шкала ручек** для времён и частот (Delay Time, High/Low Cut,
  Reverb Time/Pre) — иначе короткие задержки и низкие срезы не настроить.
  Отправляемые значения от этого не меняются.
* **Иконки** — Lucide (ISC), сконвертированы `tools/build_icons.py` в пути для
  `Shape` (векторно, перекрашиваются токенами, без растровых файлов).
* **Ячейки комбика** — боковая вкладка «Комбик»: считать (ловим дамп при
  нажатии кнопки на комбике), открыть в редакторе, записать (отправка + подсказка
  удерживать кнопку). Кэш ячеек — `slots.json` в папке данных.
* **Импорт**: .thrpreset/.json (свой формат), .syx, .YDL (выбор пресета из
  списка), одиночный 265-байтный файл. **Экспорт**: .thrpreset, .syx, .YDL.
* **Демо-симуляция** в интерфейсе: «покрутить ручку» и «выключить питание»
  демо-комбика, «нажать/удержать кнопку ячейки» — проверка синхронизации.
* **Самопроверка** `python -m thr10editor --selftest 2 --screenshot shot.png` —
  загружает QML, работает в демо, выходит с кодом 0/1 (используется в тестах и
  для проверки собранного .exe).
* **Узкое окно** (< 980 px): боковая панель становится выезжающей.

### Этап 6 — новые функции

* **Библиотека** — один JSON (`library.json`) с атомарной записью; при порче
  файл переименовывается в `.broken`, библиотека начинается заново. Поиск по
  словам: имя, папка, теги, заметки, модель усилителя, включённые блоки.
  Папки вложенные («Концерты/Клуб»), удаление папки поднимает содержимое
  на уровень выше. Ctrl+S обновляет пресет, если звук загружен из библиотеки,
  иначе открывает диалог «Сохранить».
* **A/B**: слот B при первом переключении — копия A. **У каждого слота своя
  история undo** — иначе Ctrl+Z после переключения откатывал бы правки другого
  звука. Переключение уходит на комбик одним дампом. Клавиши — **Пробел или B**
  (одна клавиша, как в ТЗ; в полях ввода пробел печатается как обычно).
* **Undo/redo**: жест (перетаскивание, колесо) склеивается в один шаг, если
  изменения одного параметра идут чаще 0,8 с. Первое чтение состояния при
  подключении не пишется в историю; повороты ручек на комбике — пишутся
  («Ручка на комбике»). LFO и промежуточные шаги морфинга — не пишутся;
  морфинг целиком — один шаг.
* **Сет-лист и «Сцена»**: сет-листы хранятся в библиотеке; режим «Сцена» —
  полноэкранный оверлей. Навигация: ←/→, ↑/↓, PgUp/PgDn, Пробел, Backspace;
  педали-«клавиатуры» работают сразу. MIDI-педаль — отдельный входной порт с
  обучением (CC/ноты по фронту нажатия, Program Change — опционально выбор
  номера).
* **Тап-темп**: среднее последних 4 интервалов, сброс после паузы 2 с, доли
  1/2…1/16 с точкой и триолью. Клавиша T, кнопка в карточке дилея и на панели.
* **Рандомайзер**: сила (насколько далеко от текущего звука), границы каждого
  параметра в положениях ручки, замки. **Master заблокирован по умолчанию** —
  защита от резкого скачка громкости. Типы эффектов, вкл/выкл блоков и модель
  усилителя меняются только по отдельным галочкам.
* **Морфинг**: в положениях ручек (частоты и времена — логарифмически),
  дискретные параметры переключаются на середине. Цель — другой слот A/B или
  пресет библиотеки. Любая ручная правка останавливает морфинг.
* **LFO**: формы синус/треугольник/меандр/пила↑↓/случайная (sample & hold),
  скорость 0,01–5 Гц, глубина в доле хода ручки. Каждый параметр обновляется не
  чаще 20 раз/с (плюс общий лимит отправки 50 сообщений/с). Остановка
  возвращает исходные значения. Ручная правка параметра под LFO сдвигает центр
  модуляции.

### Этап 7 — диагностика

* **`tools/thr_probe.py`** работает через тот же `Transport`/`SafetyGate`, что
  и редактор: отправляет только запрос состояния и изменение одного
  параметра. По умолчанию Master **на 5 тише** (безопаснее, чем громче),
  значение возвращается в `finally` даже при Ctrl+C. Проверка «принял ли
  комбик» — повторным чтением состояния. Ключ `--demo` прогоняет скрипт на
  демо-комбике (так он покрыт тестами).
* **Сборка для Windows** будет включать отдельный консольный `THR10Probe.exe`,
  чтобы проверку можно было запустить без Python.
* **`tools/parse_capture.py`** без зависимостей от Wireshark: сам читает
  pcapng/pcap (тип канала USBPcap 249), собирает SysEx из пакетов USB-MIDI
  (CIN 4–7), а если формат не USB-MIDI — ищет F0…F7 в сыром потоке.
  Направление — по биту 0x80 номера конечной точки. Всё незнакомое и
  неподтверждённое помечается `!!`. Покрыт тестами на синтетическом
  pcapng/pcap с фрагментацией дампа по пакетам.
* **Единица Delay Time** проверяется без перехвата: выставить 500 мс в
  официальном эдиторе → прочитать `thr_probe --no-change` → ожидается 5000.
