## Принятые решения

### Этап 1 — протокол

* **Источники.** Основной — SysExTones (адреса и диапазоны всех параметров).
  Раскладку дампа и минимумы независимо подтверждают реальные байты `.YDL`
  из THR_Footswitch и утилита thrpatch. Форумы Yamaha, Википедия и сайт
  Yamaha недоступны из среды разработки — ссылки на них оставлены в
  `docs/PROTOCOL.md` для ручной проверки.
* **Лицензии источников** (AGPL/GPL/BSD): код не копируем, реализуем заново по
  фактам (байты, смещения), источники указываем.
* **Lamp/Wide** (системные команды `30`) — один источник, подозрительный
  формат → `UNCONFIRMED`, не отправляются.
* **Запись в ячейки 1–5**: SysEx-команды нет в источниках → редактор
  отправляет звук в текущее состояние, сохраняет пользователь удержанием
  кнопки на комбике. Чтение ячейки — через дамп, который комбик шлёт при
  нажатии кнопки.
* **Единицы отображения** (0,1 мс, 0,1 с, «Thru») — `DERIVED`, на байты не
  влияют. Единица Delay Time вынесена в константу — от неё зависит тап-темп.

### Этап 2 — протокол и модель

* **Стек и версии** (проверено в среде разработки): Python 3.12/3.13,
  PySide6 6.12.0, mido 1.3.3, python-rtmidi 1.5.8, pytest 9.2.0,
  PyInstaller 6.22.3. **Для Windows — Python 3.12 (64-bit)**: у
  python-rtmidi 1.5.8 нет колёс для Windows под Python 3.13+, а сборка из
  исходников требует MSVC. Выбор PySide6 + QML — по ТЗ; QML даёт плавные
  анимации, масштабирование и HiDPI без ручной отрисовки.
* **Логические значения в модели.** Вкл/выкл хранится как 1/0, а в протоколе
  00 = вкл, 7F = выкл. Перевод делает `ParamDef.to_raw/from_raw`.
* **Параметры разных типов эффекта** (Stomp/Rack, Chorus/Flanger/…,
  Hall-Room-Plate/Spring) делят адреса. В модели они хранятся раздельно
  (`comp.stomp.sustain` и `comp.rack.threshold`), в дамп пишутся только
  активные. При разборе дампа значения неактивных типов берутся из
  текущего состояния — переключение типа не теряет настройки.
* **SafetyGate** — последний фильтр перед комбиком: пропускает только
  изменение известного параметра в допустимом диапазоне, запрос состояния
  и корректный дамп. Неподтверждённые команды открываются только через
  `protocol_overrides.json`.
* **Имена пресетов на комбике**: только ASCII, ≤ 64 символа; кириллица
  транслитерируется (в библиотеке редактора имя хранится как есть).
* **Тестовые данные**: реальные байты двух пресетов из THR_Footswitch
  (`tests/fixtures.py`) — проверяют раскладку дампа и чтение .YDL.

### Этап 3 — транспорт

* **Один интерфейс** `Transport` (`open/close/send/poll`) для MIDI и демо.
  Приём — опросом (`poll`) из такта сессии: без потоков, безопасно для Qt.
* **Демо-комбик** (`DemoAmp`) работает на уровне байтов SysEx через тот же
  слой протокола: отвечает дампом на запрос, шлёт heartbeat 2 раза/с,
  умеет «крутить ручки» и «нажимать кнопки ячеек» — так проверяется
  синхронизация без железа.
* **MidiTransport** ищет порт по подстроке «THR» (предпочитает вход и выход с
  одинаковым именем), каждое сообщение проверяет `SafetyGate`. Если
  python-rtmidi недоступен — понятная ошибка, приложение остаётся в демо.
* **Ограничение частоты**: ≤ 1 сообщения за 20 мс, склейка по параметру,
  барьеры на смене типа, пауза 60 мс после дампа.
* **Сессия** (`app/session.py`, без Qt): статус связи (heartbeat/таймауты),
  подавление эха (если комбик вернёт наше же значение в течение 0,6 с, оно
  игнорируется), повторный запрос состояния после смены типа/модели
  ручкой на комбике, автопереподключение раз в 3 с после ошибки.
* **Загрузка пресета** уходит одним дампом; правки, морфинг и LFO —
  отдельными сообщениями; undo/рандом — отдельными, если изменений ≤ 8,
  иначе дампом.

### Этап 4 — дизайн

* **Направление «Graphite & Glow»**: графитовая тёмная тема + тёплая светлая,
  один янтарный акцент (отсылка к подсветке THR), свой оттенок у каждого блока
  эффектов. Подробно — `docs/DESIGN.md`.
* **Токены** — `thr10editor/ui/theme/tokens.json`; в QML доступны через
  синглтон `Theme` (размеры уже умножены на масштаб). Тест проверяет
  одинаковость ключей тем и контраст WCAG.
* **Шрифт Inter** (OFL) встроен в TTF: npm-пакет `inter-ui` 4.1.1 (woff2)
  сконвертирован fontTools. Причина — одинаковая типографика на любой
  Windows, кириллица и табличные цифры.
* **Светлый акцент** затемнён до `#A35E00`, чтобы белый текст на кнопках
  имел контраст ≥ 4,5:1.

### Этап 5 — базовый интерфейс

* **QML + синглтоны** `Theme` и `Backend` (модуль `THR10`). Каждому параметру
  соответствует `ParamItem` (значение, текст, положение ручки, активность),
  каждому блоку — `GroupItem` (вкл/выкл, тип, список ручек для текущего типа).
* **Стиль Qt Quick Controls — Basic**: нативный стиль Windows не даёт полностью
  перекрасить контролы под токены.
* **Логарифмическая шкала ручек** для времён и частот (Delay Time, High/Low Cut,
  Reverb Time/Pre) — иначе короткие задержки и низкие срезы не настроить.
  Отправляемые значения от этого не меняются.
* **Иконки** — Lucide (ISC), сконвертированы `tools/build_icons.py` в пути для
  `Shape` (векторно, перекрашиваются токенами, без растровых файлов).
* **Ячейки комбика** — боковая вкладка «Комбик»: считать (ловим дамп при
  нажатии кнопки на комбике), открыть в редакторе, записать (отправка + подсказка
  удерживать кнопку). Кэш ячеек — `slots.json` в папке данных.
* **Импорт**: .thrpreset/.json (свой формат), .syx, .YDL (выбор пресета из
  списка), одиночный 265-байтный файл. **Экспорт**: .thrpreset, .syx, .YDL.
* **Демо-симуляция** в интерфейсе: «покрутить ручку» и «выключить питание»
  демо-комбика, «нажать/удержать кнопку ячейки» — проверка синхронизации.
* **Самопроверка** `python -m thr10editor --selftest 2 --screenshot shot.png` —
  загружает QML, работает в демо, выходит с кодом 0/1 (используется в тестах и
  для проверки собранного .exe).
* **Узкое окно** (< 980 px): боковая панель становится выезжающей.

### Этап 6 — новые функции

* **Библиотека** — один JSON (`library.json`) с атомарной записью; при порче
  файл переименовывается в `.broken`, библиотека начинается заново. Поиск по
  словам: имя, папка, теги, заметки, модель усилителя, включённые блоки.
  Папки вложенные («Концерты/Клуб»), удаление папки поднимает содержимое
  на уровень выше. Ctrl+S обновляет пресет, если звук загружен из библиотеки,
  иначе открывает диалог «Сохранить».
* **A/B**: слот B при первом переключении — копия A. **У каждого слота своя
  история undo** — иначе Ctrl+Z после переключения откатывал бы правки другого
  звука. Переключение уходит на комбик одним дампом. Клавиши — **Пробел или B**
  (одна клавиша, как в ТЗ; в полях ввода пробел печатается как обычно).
* **Undo/redo**: жест (перетаскивание, колесо) склеивается в один шаг, если
  изменения одного параметра идут чаще 0,8 с. Первое чтение состояния при
  подключении не пишется в историю; повороты ручек на комбике — пишутся
  («Ручка на комбике»). LFO и промежуточные шаги морфинга — не пишутся;
  морфинг целиком — один шаг.
* **Сет-лист и «Сцена»**: сет-листы хранятся в библиотеке; режим «Сцена» —
  полноэкранный оверлей. Навигация: ←/→, ↑/↓, PgUp/PgDn, Пробел, Backspace;
  педали-«клавиатуры» работают сразу. MIDI-педаль — отдельный входной порт с
  обучением (CC/ноты по фронту нажатия, Program Change — опционально выбор
  номера).
* **Тап-темп**: среднее последних 4 интервалов, сброс после паузы 2 с, доли
  1/2…1/16 с точкой и триолью. Клавиша T, кнопка в карточке дилея и на панели.
* **Рандомайзер**: сила (насколько далеко от текущего звука), границы каждого
  параметра в положениях ручки, замки. **Master заблокирован по умолчанию** —
  защита от резкого скачка громкости. Типы эффектов, вкл/выкл блоков и модель
  усилителя меняются только по отдельным галочкам.
* **Морфинг**: в положениях ручек (частоты и времена — логарифмически),
  дискретные параметры переключаются на середине. Цель — другой слот A/B или
  пресет библиотеки. Любая ручная правка останавливает морфинг.
* **LFO**: формы синус/треугольник/меандр/пила↑↓/случайная (sample & hold),
  скорость 0,01–5 Гц, глубина в доле хода ручки. Каждый параметр обновляется не
  чаще 20 раз/с (плюс общий лимит отправки 50 сообщений/с). Остановка
  возвращает исходные значения. Ручная правка параметра под LFO сдвигает центр
  модуляции.

### Этап 7 — диагностика

* **`tools/thr_probe.py`** работает через тот же `Transport`/`SafetyGate`, что
  и редактор: отправляет только запрос состояния и изменение одного
  параметра. По умолчанию Master **на 5 тише** (безопаснее, чем громче),
  значение возвращается в `finally` даже при Ctrl+C. Проверка «принял ли
  комбик» — повторным чтением состояния. Ключ `--demo` прогоняет скрипт на
  демо-комбике (так он покрыт тестами).
* **Сборка для Windows** будет включать отдельный консольный `THR10Probe.exe`,
  чтобы проверку можно было запустить без Python.
* **`tools/parse_capture.py`** без зависимостей от Wireshark: сам читает
  pcapng/pcap (тип канала USBPcap 249), собирает SysEx из пакетов USB-MIDI
  (CIN 4–7), а если формат не USB-MIDI — ищет F0…F7 в сыром потоке.
  Направление — по биту 0x80 номера конечной точки. Всё незнакомое и
  неподтверждённое помечается `!!`. Покрыт тестами на синтетическом
  pcapng/pcap с фрагментацией дампа по пакетам.
* **Единица Delay Time** проверяется без перехвата: выставить 500 мс в
  официальном эдиторе → прочитать `thr_probe --no-change` → ожидается 5000.

### Этап 8 — полировка и сборка

* **Сборка** — `scripts/build_exe.py` (PyInstaller, spec генерируется
  скриптом) и `scripts/build_windows.bat` (venv → зависимости → тесты →
  сборка → самопроверка .exe). Результат: `THR10Editor.exe` (onefile, без
  консоли) и `THR10Probe.exe` (консоль, без Qt).
* **`PySide6-Essentials` вместо полного `PySide6`**: приложению хватает
  базовых модулей (проверено тестами и самопроверкой); полный пакет тащит
  WebEngine, и onefile вырастал до 206 МБ. Плюс из сборки вырезаются стили
  Controls кроме Basic и QML-модули, которые не используются. Пробная
  сборка в среде разработки (Linux): 82 МБ, самопроверка бинарника — OK.
  На Windows сборка не проверялась (нет Windows в среде разработки) —
  скрипт рассчитан на неё, первый запуск `build_windows.bat` покажет.
* **Иконка** рисуется из токенов (`tools/make_icon.py`), ICO с размерами
  16–256 собирается без Pillow.
* **Окно** запоминает размер и «развёрнуто».
* **Подписи параметров** в списках рандомайзера/LFO и истории содержат тип
  эффекта («Output (Rack)»), чтобы не путать одноимённые ручки.

### После этапа 8 — готовый .exe

* **Сборка на Windows — GitHub Actions** (`.github/workflows/build-windows.yml`):
  в среде разработки только Linux, а PyInstaller не собирает под другую ОС.
  На `windows-latest` с Python 3.12: тесты → `scripts/build_exe.py`
  (с самопроверкой редактора) → проверка `THR10Probe.exe --demo` →
  публикация в Releases с тегом `v<версия>` (повторная сборка той же версии
  заменяет файлы) и в артефакты запуска.
* Скрипты не падают на кириллице, если вывод перенаправлен в однобайтной
  кодировке Windows (`reconfigure(errors="replace")`).

### Версия 1.1 — редизайн «Studio Graphite»

* **Почему.** Первая версия дизайна выглядела «детской»: радужные дуги ручек и
  цветные переключатели у каждого блока, «таблетки» вместо сегментных
  переключателей, плоские ручки с толстым указателем, много залитых янтарных
  кнопок, логотип-квадратик.
* **Что сделано.** Нейтральный графит + один янтарный акцент; цвет блока
  только в тонкой риске у края карточки. Ручки: шкала с рисками, фаска,
  градиент, тень, тонкая дуга с мягким свечением. Кнопки питания блоков с
  «LED». Сплошные сегментные переключатели с переезжающим индикатором,
  вкладки с подчёркиванием, скругления 4–9 px, блики по кромкам, «утопленные»
  поля, свой SpinBox, знак-ручка вместо квадратика, тёплое свечение фона.
* **Анимации** (короткие, по делу): появление карточек по очереди, плавный
  доворот ручек при загрузке/undo/A/B, вспышка ручки при значении с комбика,
  свечение кнопки питания, переезд индикаторов и подчёркиваний, смена вкладок
  со сдвигом, мягкая смена имени звука и модели, «дыхание» LED связи,
  пульсация ожидающей ячейки, вспышка тап-пада, подъём сообщений.
* **Вспышка синхронизации** — сигнал `ParamItem.flash`: бэкенд шлёт его, когда
  значение пришло с комбика (не более 3 параметров за раз, чтобы дамп целиком
  не «мигал» всеми ручками).
* Версия приложения — 1.1.0 (новый релиз в GitHub).

### Версия 1.2 — исправления по результатам проверки

1. **Рандомайзер меняет всё**: ручки, вкл/выкл блоков и выбор из списка
   (модель, кабинет, типы эффектов, Ratio/Knee). Галочки «менять типы /
   блоки / модель» убраны — вместо них замки на каждом параметре (в панели
   рандомайзера видны все параметры). «Сила» для дискретных параметров —
   вероятность смены. По умолчанию заблокирован только Master. Старые
   настройки `types/switches/amp` игнорируются.
2. **«Сохранить» всегда создаёт новый пресет** (`saveCurrentAs`) из снимка
   текущих значений всех параметров — включая параметры неактивных типов
   эффектов; звук в редакторе не меняется, новый пресет становится активным.
   Перезапись — только `overwritePreset` из контекстного меню пресета
   («Перезаписать текущим звуком…») с подтверждением; имя/папка/теги
   сохраняются. Ctrl+Shift+S убран (Ctrl+S и так «как новый»). «Добавить
   текущий звук» в сет-лист при изменённом звуке тоже создаёт новый пресет.
   Причина «сброса» звука при сохранении — горячие клавиши срабатывали при
   вводе имени (пробел переключал A/B, T — тап-темп); исправлено в п. 3.
3. **Завершение ввода текста — один общий механизм** `TextInputGuard`
   (`thr10editor/ui/text_input.py`, синглтон `InputGuard`): фильтр событий
   окна. Клик в любом месте вне поля или Enter в однострочном поле убирают
   фокус → поле шлёт `editingFinished` и сохраняет текст; в многострочном
   поле Enter — новая строка, завершение — Ctrl+Enter или клик вне. Пока
   редактируемое поле в фокусе, все `Shortcut` приложения выключены
   (`!InputGuard.editing`). Поле может отключить завершение по Enter
   (`finishOnEnter: false` — ввод значения ручки при ошибке). Редактируемый
   `AppCombo` теперь на TextField (раньше в нём нельзя было печатать).
   **Найден баг**: сочетания из нескольких клавиш (`["Space","B"]`, стрелки
   сцены, Ctrl+Y, Ctrl+=) превращались во вложенный список и молча не
   работали — `Array.isArray` ложен для списка из `property var`.
   Тесты: `tests/test_text_input.py` (живая QML-сцена),
   `tests/test_app_scenarios.py` (настоящее окно: ввод имени с пробелом, B, T
   не трогает A/B и тап-темп; клик вне сохраняет имя).
4. **Ожидание педали MIDI-контроллера отменяется**: Esc, клик в любом месте
   окна (прозрачный слой поверх всего на время ожидания) и повторное нажатие
   той же кнопки (`ControllerMapper.learn` — переключатель,
   `cancel_learn`). Прежняя привязка при отмене не меняется. Работает и без
   подключённого порта.
5. **Режим «Сцена».** Причина неработающих клавиш — п. 3: сочетания
   из нескольких клавиш не регистрировались, и пробел «нажимал» кнопку
   «Режим «Сцена»» в фокусе (старт с первого трека). Теперь клавиши
   обрабатывает сам `StageView` (FocusScope + Keys): Пробел/→/↓/PgDn —
   следующий, ←/↑/PgUp/Backspace — предыдущий, Esc — выход; при старте фокус
   переходит сцене, кнопки сцены фокус не берут.
   **Данные трека**: `SetlistTrack {preset, chords, tuning, background}` в
   `library.json` (старый формат — список id — читается). Редактор трека —
   кнопка-карандаш в сет-листе: строй (редактируемый список с вариантами
   Standard E, Drop D, Eb Standard, D Standard, Drop C…), аккорды
   (многострочное поле), фон (PNG/JPG/WEBP копируется в
   `%APPDATA%\THR10Editor\backgrounds\` под уникальным именем; замена и
   удаление чистят неиспользуемые файлы). На сцене: строй и аккорды крупно
   (шрифт уменьшается, если текста много), фон — PreserveAspectCrop +
   затемнение-градиент, текст светлый; без фона — обычный фон темы.
   Тесты: модель (старый формат, сохранение), бэкенд (копирование, замена,
   удаление, отказ для не-картинок), сценарий на настоящем окне (фокус на
   кнопке → пробел/стрелки/PgDn/PgUp/Esc, аккорды/строй/фон на экране).
6. **Светлая тема: мягче оранжевые кнопки.** Новые токены `accentFill`,
   `accentFillHover`, `accentFillText` (главная кнопка, включённый
   переключатель). Светлая тема: заливка `#F0A24A` (было `#A0590E`), текст на
   ней тёмный `#2A1804` — контраст 8,1:1 (hover 7,2:1); акцент для текста и
   линий чуть светлее — `#AA6015` (4,6:1 на поверхности). Тёмная тема: новые
   токены равны прежним значениям — визуально без изменений (проверяется
   тестом). Версия 1.2.0.

### Версия 1.3 — картинки и GIF: фон, обложка трека, карточки модулей

Запрос: вставлять не только фото, но и GIF (видео — отменено пользователем:
QtMultimedia нет в PySide6-Essentials, а пакет Addons добавил бы ~40 МБ к
.exe); картинки не по размеру — **растягивать на всю область, а не
обрезать**; обложка трека по центру поверх фона; картинка/GIF в карточках
модулей.

1. **GIF** принимается везде, где картинка (`BACKGROUND_EXTENSIONS`
   + `.gif`); проверка — `QImageReader` (битый файл отклоняется). Видео
   (`.mp4` и т. п.) отклоняется с сообщением. Показ — общий компонент
   `components/MediaImage.qml`: `Image` или `AnimatedImage` (для GIF;
   анимация играет только пока элемент видим).
2. **Фон сцены растягивается** (`Image.Stretch`) на весь экран без обрезки
   (было PreserveAspectCrop). Затемнение-градиент поверх оставлено — иначе
   текст не читается на светлых картинках.
3. **Обложка трека**: поле `SetlistTrack.cover` (старые файлы без него
   читаются). На сцене — по центру между номером трека и именем, в своих
   пропорциях (рамка подстраивается под картинку, поэтому без искажения и
   без обрезки); высота 30 % экрана, 20 % если есть аккорды. В редакторе
   трека — отдельная строка «Обложка трека» (выбрать/заменить/убрать).
   Решение: обложку не растягиваем — пропорции рамки берутся из картинки,
   так что «не по размеру» для неё не бывает.
4. **Картинка в карточках модулей** (усилитель, компрессор, модуляция,
   дилей, реверб, гейт): кнопка с иконкой «картинка» в заголовке карточки
   или перетаскивание файла на карточку. Пока картинки нет — место не
   занимается (чтобы не загромождать окно). В карточке эффекта — полоса
   2:1 по ширине карточки, у усилителя — справа от ручек, если ручки
   помещаются в один ряд, иначе полосой 3:1 под ними. Картинка
   растягивается на область. При наведении — «Заменить» и «Убрать».
   Картинки модулей общие для всех пресетов (это оформление, а не звук):
   `settings.json` → `module_media` {группа: файл}.
5. Все файлы копируются в `%APPDATA%\THR10Editor\backgrounds\` под
   уникальными именами; уборка неиспользуемых учитывает фоны, обложки и
   картинки модулей.
   Тесты: модель (обложка, GIF в списке, видео нет), бэкенд (GIF как фон,
   отказ видео, обложка отдельно от фона — замена/удаление/уборка, картинки
   модулей — сохранение после перезапуска, замена, удаление), сценарии на
   настоящем окне (фон растянут на всё окно, обложка-GIF по центру и
   анимируется, 6 карточек с кнопкой, картинка появляется/исчезает,
   растянута). Тестовый GIF собирается без сторонних библиотек
   (`tests/gif_sample.py`). Версия 1.3.0.
