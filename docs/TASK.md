# Техническое задание

Задача: написать с нуля современный редактор звука для гитарного комбика Yamaha THR10 первого поколения (не THR-II), заменяющий официальный Yamaha THR Editor V1.1.0.

## Контекст
- ОС: Windows, ноутбук. Драйвер Yamaha Steinberg USB установлен, официальный THR Editor V1.1.0 тоже установлен и работает (его можно использовать для сравнения и для перехвата трафика).
- Я знаю Python и C++. Комбик у меня есть, но у тебя к нему доступа нет: на железе я проверю всё сам после того, как ты закончишь, по чек-листу из этапа 7.
- Официальный эдитор выглядит устаревшим, у него фиксированный маленький размер окна, его нельзя развернуть. Новый должен решить эти проблемы и добавить функции.
- Обработка звука на компьютере (лупер, эффекты через USB-аудио) не нужна: играть с задержкой я не хочу. Всё работает только через управление параметрами комбика.

## Как редактор общается с комбиком
- THR10 подключается по USB как MIDI-устройство, параметры передаются через SysEx-сообщения.
- Не выдумывай байты SysEx. Сначала найди открытые описания протокола THR10 (первое поколение), которые сделали энтузиасты, и опирайся на них. Явно указывай, какие команды взяты из источников, а какие не подтверждены.
- На случай нехватки данных подготовь пошаговую инструкцию, как перехватить трафик между официальным эдитором и комбиком (USBPcap + Wireshark), и скрипт, который разберёт мой дамп (см. этап 7).
- Безопасность: отправляй на комбик только команды изменения параметров и чтения состояния. Никаких сообщений, связанных с прошивкой, сбросом или служебными режимами, пока протокол не подтверждён.
- Нужен режим «без комбика» (демо/офлайн), чтобы интерфейс можно было разрабатывать и проверять без подключения.

## Функции
Базовые (паритет с оригиналом):
- все модели усилителей THR10 и все параметры: Gain, Master, Bass, Middle, Treble, компрессор, гейт, модуляции, дилей и реверб со всеми их настройками;
- синхронизация состояния с комбиком: при подключении прочитать текущие настройки, а если ручку покрутили на самом комбике, интерфейс обновляется;
- работа с пятью пользовательскими ячейками пресетов комбика;
- импорт и экспорт пресетов, включая родные файлы библиотек официального эдитора (.YDL), если формат удастся разобрать.

Новые функции:
1. Библиотека пресетов без ограничения количества, с папками, тегами, поиском и избранным.
2. A/B-сравнение: два слота звука, переключение одной клавишей.
3. История изменений: undo/redo (Ctrl+Z / Ctrl+Y) для всех параметров.
4. Морфинг: плавный переход между двумя пресетами за заданное время.
5. Рандомайзер с настраиваемыми границами и фиксацией отдельных параметров (замок на ручке).
6. Сет-лист для выступлений: упорядоченный список пресетов, крупный полноэкранный режим «сцена», переключение стрелками, пробелом, а также с MIDI-контроллера или ножной педали, если она подключена.
7. Тап-темп для дилея (клавиша или кнопка мыши).
8. Медленная автоматизация параметров (LFO с формой волны, скоростью и глубиной, например для свипа громкости или тембра). Учти ограничения скорости MIDI и не забивай порт сообщениями: ограничивай частоту отправки.

## Дизайн
- Современный, не старомодный: тёмная тема по умолчанию плюс светлая, аккуратная типографика, плавные анимации, единая дизайн-система (цвета, отступы, скругления как токены).
- Окно свободно меняет размер и разворачивается на весь экран, интерфейс адаптивно масштабируется. Корректная работа на HiDPI (масштаб 125–200%).
- Ручки: крутятся перетаскиванием мышью и колесом, точная подстройка с Shift, двойной клик сбрасывает значение по умолчанию, рядом показывается числовое значение, которое можно ввести с клавиатуры.
- Горячие клавиши для всех основных действий и экран со списком клавиш.
- Индикатор состояния подключения к комбику, понятные сообщения об ошибках.
- Визуальное направление выбери сам (см. этап 4 в «Порядке работы»).

## Технологии
- Стек: Python + PySide6 (QML для современного интерфейса) + mido/python-rtmidi для MIDI. Обоснование выбора и версии зависимостей запиши в docs/PROGRESS.md; зависимости зафиксируй в requirements.txt.
- Архитектура слоями: протокол (кодирование и декодирование SysEx) → модель состояния → UI. Протокол не должен зависеть от интерфейса.
- Юнит-тесты на кодирование и декодирование сообщений и на логику пресетов, морфинга и undo.
- Итоговая сборка: один .exe для Windows (например, через PyInstaller) и инструкция по запуску.

## Порядок работы
Сделай весь проект целиком за один запуск, без остановок между этапами и без вопросов ко мне, если они не блокируют работу полностью. Спорные решения принимай сам, выбирая разумный вариант, и записывай их с обоснованием в docs/PROGRESS.md.

Этапы (выполняй подряд, после каждого — тесты и коммит с понятным сообщением):
1. Исследование протокола THR10 по открытым источникам. Результат — docs/PROTOCOL.md: все команды и параметры, для каждого указан источник и статус (подтверждено источником / не подтверждено).
2. Слой протокола (кодирование и декодирование SysEx) и модель состояния со всеми параметрами + юнит-тесты.
3. Транспорт: реальный MIDI (mido/python-rtmidi) и демо-режим без комбика за одним интерфейсом. Приложение должно полностью работать в демо-режиме.
4. Дизайн: выбери сам одно современное визуальное направление (тёмная тема по умолчанию + светлая), опиши его в docs/DESIGN.md и вынеси все цвета, шрифты, отступы и скругления в токены, чтобы стиль можно было легко поменять.
5. Базовый UI с паритетом функций оригинала.
6. Все новые функции: библиотека пресетов → A/B → undo/redo → сет-лист → тап-темп → рандомайзер → морфинг → автоматизация.
7. Диагностика для проверки на железе: скрипт tools/thr_probe.py (находит MIDI-порт THR10, читает состояние, безопасно меняет один параметр, например Master, и возвращает его обратно, всё логирует в файл) и docs/HARDWARE_TEST.md — пошаговый чек-лист, что мне проверить на реальном комбике и что прислать тебе при ошибке (лог, описание). Отдельно — инструкция по перехвату трафика официального эдитора (USBPcap + Wireshark) и скрипт разбора дампа, на случай если протокол из источников окажется неточным.
8. Полировка дизайна, сборка .exe через PyInstaller (скрипт сборки + инструкция), README с инструкцией по установке и запуску.

В конце дай короткий отчёт: что сделано, что не подтверждено на железе, с чего мне начать проверку.

Если протокол из источников неполный, не останавливайся: реализуй то, что подтверждено, остальное пометь в коде и в docs/PROTOCOL.md как «требует проверки», а в интерфейсе такие параметры должны работать в демо-режиме и не отправляться на комбик, пока я не подтвержу их перехватом трафика.
